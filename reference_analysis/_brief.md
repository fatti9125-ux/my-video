## 1. Extract and inspect every frame

1. Use FFprobe and FFmpeg, or equivalent tools already installed. Decode every video frame in display order to lossless native-resolution PNGs. Preserve a frame-to-PTS index. Decode audio to PCM at its native sample rate with original channels for listening and timing. Quote filenames and use a path-safe argument list when scripting. Record file identity, extraction settings, and output counts so the analysis can resume after a context reset.
2. Make an overview contact sheet at approximately one frame per second. Use it to identify shot boundaries, reframes, overlay changes, reaction beats, maps, and related motion. Then make chronological sheets with **every** source frame, grouped in manageable windows. Aim for 3–4 columns and 6–12 frames per sheet at readable size. Label each tile outside the picture with frame index and PTS. Open the sheets with an image-capable tool. Open individual frames or native-size crops when the face, lettering, or compositing is hard to judge. View sequential frames at normal speed and in slow playback where your tools support it.
3. Use image differences or scene detection to flag cuts, brightness changes, or possible duplicate holds. Use region-specific diffs around brows, mouth, hands, feet, props, and text to catch changes too small for full-frame metrics. Treat metric spikes as candidates. A stamp, white flash, fire loop, or fast zoom can produce a large spike inside one shot. Compression shimmer can register as motion during a hold. Confirm visually and use the neighboring frames.
4. For every shot, record its establishing state, first visible change, anticipation, action, overshoot if present, recovery, hold, and cut. Track a separate state or curve for every changing layer. Inspect a short before/after sequence for every cut, pose swap, graphic entrance, impact, and finish. Identify the first and last source frames of each active span. Compare animated regions to establish whether they move per frame, on repeated drawings, or in mixed cadences. If pose swaps land at irregular intervals, keep the real durations.
5. Write a frame index with one row per decoded frame and link each row to its shot and visual state. Describe real state changes as event spans. A visually checked hold may share one state across consecutive frame rows. Continuous camera, puppet, and effects motion should point to measured keys or tracked samples. Extra notes go on the frames that introduce, change, or resolve something. This keeps the report readable while accounting for every source frame.
6. Complete one clip before opening the next. Record how many frames you decoded and inspected, which shots were verified, which audio spans were played, and the last verified frame. Keep a progress file on disk and resume at the next uncovered interval. Label any range you could decode but could not visually inspect as `decoded only`. If there is no audio playback, label a waveform-derived cue `unverified` and leave its sound identity blank. Finish supported work and report actual coverage.

Example commands for one clip. Create the output directories before running. Change the path for each clip and verify local command support. The commands use quoting that works in PowerShell and in a POSIX shell.
